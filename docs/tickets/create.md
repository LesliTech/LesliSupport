# Create a Ticket

Open `/support/tickets/new` or select **Create ticket** from the ticket list.

The form accepts:

| Field | Source |
| --- | --- |
| Subject | Free text |
| Type | Items in the account's `Ticket Types` catalog |
| Category | Items in the account's `Ticket Categories` catalog |
| Priority | Items in the account's `Ticket Priorities` catalog |
| Owner | Users in the current account |
| Description | Free text |

The ticket identifier is generated by the application and is not editable. On success, the interface redirects to the new ticket.

## Form layout

The ticket form is rendered by `app/views/lesli_support/tickets/_form.html.erb` with `LesliView::Forms::Builder`. Shared controls—including labels, validation messages, selects, the description textarea, and the submit action—remain the responsibility of the form builder.

Layout and one-off presentation in the partial use Tailwind CSS utilities:

- The generated ticket identifier is displayed as a disabled, full-width field.
- Type, category, and priority stack on small screens and use a three-column grid from the `md` breakpoint onward.
- The owner and description controls remain full width below the classification grid.

Keep new layout changes in Tailwind utilities and do not reintroduce the legacy Bulma `field`, `control`, `columns`, `column`, `input`, or `has-text-centered` classes.

## Troubleshooting

If a selector is empty, verify that its named catalog and items exist for the current account. Catalog names are part of the current form contract and must match exactly.
